# 独立笔记本

这是助手中的独立笔记窗口。Vditor 仅负责 Markdown 编辑与呈现；文件结构、附件生命周期、同步和窗口集成由本项目维护。菜单栏 / Windows 托盘左键浮层及右键菜单的“笔记本”打开窗口，关闭窗口会先保存再隐藏；退出应用会等待保存，失败则保留窗口。

## 使用

标题栏由 AppKit / WPF 原生控件承载，拖动和双击最大化不再依赖异步网页消息；窗口有细边框与圆角。Windows 11 使用 DWM，Windows 10 使用原生区域裁剪网页子窗口；macOS 使用系统圆角。列表压缩为两行，工具栏提示向下显示，避免编辑器顶部裁切。

“最近使用”下方固定显示“快速笔记”。其目录固定为 `books/quick-notes`，其他元数据、笔记目录、附件回收与 WebDAV 同步均与普通笔记相同，不重复列在普通笔记本区。首次打开创建“随手记”，重复打开选中该本最近修改的笔记，不重复新建；可用加号创建更多笔记。“设置 → 快捷键”可分别录入打开上次笔记页面、打开快速笔记两个全局快捷键，默认留空，音频关闭时仍可用。上次笔记 ID 与列表位置存入本机 `.state.json`，重启后恢复；笔记移动后跟随 ID，已删除则打开其他最近笔记。

左侧第一列以紧凑行管理笔记本，第二列选择和搜索笔记。侧栏分隔条以居中短线提示悬停和键盘焦点，避免首次打开时出现整条蓝色；保留拖拽、左右方向键调宽和双击复位。新建和重命名输入框打开时默认全选现有名称，直接输入即可替换；按回车确认，取消按钮与 Esc 仍然取消。正文随窗口铺满可用宽度。笔记本右键菜单支持新建笔记、重命名、打开文件夹、删除；笔记右键菜单支持打开、重命名、移动、打开文件夹、回收。删除笔记本会连同笔记及附件完整移入回收站，可整本恢复；固定快速笔记本保留新建及文件夹入口。正文右上角也保留笔记操作。“回收站”在笔记本主框架中单独显示，集中管理笔记本、笔记和附件，可恢复或确认后永久删除。整篇笔记与笔记本不会按附件规则自动清理；永久删除会在后续同步时传播，无法撤销。

默认“可编辑预览”直接支持段落、标题、列表、表格和任务勾选。代码块使用统一圆角外框，编辑时以不占尺寸的柔和高亮标识，源码与预览内边距、滚动高度一致，点击代码正文直接编辑，桌面端复制左侧提供“弹出编辑”按钮，也不会额外滚动正文；新建代码块直接插入当前空行，不把插入片段的格式换行变成额外空段落；激活空块不写入占位换行，代码内部的实际空行保留；语言栏在预览和编辑时保持位置一致，可通过下拉框重新选择语言；编辑时只显示一份等宽源码区域。新建后直接进入代码正文，自动识别常见语言，不确定时以 txt 显示；自动识别不改写围栏语言，手动选择会保存到 Markdown，支持撤销与重做。点击正文其他位置恢复预览。复制只取代码正文，保留代码内部空行、Tab、缩进和末尾空格，去掉闭合围栏前的一个结构换行；主动添加的末尾空行保留，鼠标点击复制保留编辑光标。编辑会展开当前代码块，不跳转整个页面。源码与预览共用撤销历史，主题切换保留编辑状态。模式切换优先以视区第一行的段落或代码行恢复阅读位置，考虑源码换行和代码内部滚动；用户滚动、点击或输入后立即停止自动校正。特殊 Markdown 无法一一映射时保留阅读进度，文件边缘按可滚动范围限制位置。图片从原生文件服务读取，在插入渲染 DOM 前解析显示地址，正文仍保留 `reference/` 相对路径。`src/images.mjs` 适配固定版本的 Lute IR 渲染接口，升级编辑器必须重跑图片导入、重新打开和正文路径检查。Vditor 会规范化部分 Markdown 空白、表格和任务标记格式，因此不承诺整份文件逐字节不变。

附件可以拖入、粘贴或用附件面板添加；保存为笔记内的相对链接。原文件保留，笔记获得自己的副本。引用消失后默认等待 30 秒，可在“我的笔记库”调整为 5–3600 秒；随后移动至该笔记的 `.trash/`。撤销恢复引用时自动移回 `reference/`，也可从附件面板“已回收”恢复并插入。入回收站满 15 天后，巡检才允许永久删除附件和对应备份。

“我的笔记库”可配置 Nextcloud 的 **HTTPS WebDAV 专用文件夹地址**、账号和应用密码。在线目录须已创建；首次绑定会上传本地笔记并下载在线内容，保留本地离线副本。改变账号或地址重新建立同步基线，不自动清空任何一边。请使用专用目录，避免混入普通 Nextcloud 文件。

外部程序修改正文时，保存会停止并保留恢复稿。点击底部保存状态可选择保留当前内容或载入磁盘版本，两份内容先备份到 `.quarantine/`。同步冲突同样保留双方版本，从“同步结果 → 处理冲突”主动打开对照窗口，背景失败不会强制弹窗打断编辑。

## 文件结构

本地库位于两端用户的 `Documents/AssistantNotebook`，绑定 WebDAV 不移动文件，不再提供迁移入口。已有旧版自定义目录继续读取，以免升级后遗漏现有笔记；网盘配置不会改变其路径。

```text
books/<book-id>/
  book.json
  <note-id>/
    note.json
    main.md
    reference/<attachment-name>-<uuid>.<ext>
    .trash/<attachment-name>-<uuid>.<ext>
    .attachments.json
.deleted/<note-id>/       # 整篇笔记的可恢复删除
.deleted-books/<book-id>/ # 整本笔记本和笔记的可恢复删除
.drafts/<note-id>.md      # 保存失败时的恢复稿
.conflicts/<id>/          # 同步冲突的两个版本
.quarantine/<id>/         # 应用在线删除/替换前与外部冲突的备份
.state.json
.sync.json               # 本机逐文件哈希基线和冲突状态
.sync-report.json        # 最近一轮按笔记/笔记本汇总的完成结果及错误
```

正文、附件、笔记本/笔记元数据及整篇笔记/整本笔记本回收目录同步至 WebDAV；本机状态、恢复稿、冲突备份、隔离备份及 `.bak` 不上传。这些本机恢复数据不会因更换网盘地址而清空。显示名称不作为文件身份，重命名不会改稳定 ID。

## 数据保障

- 文件服务限定在用户选定的笔记库内，拒绝路径穿越、符号链接和 Windows 目录联接。
- 同一窗口的文件操作使用串行队列；原子替换保留上一版本 `.bak`。损坏 JSON 可从有效备份恢复。
- 附件回收先写意图记录再移动，崩溃重试不会重置 15 天计时。未保存稿和磁盘恢复稿的引用同样保护附件。
- 每小时巡检，启动与系统唤醒补跑；活动笔记每 10 秒校验引用。程序退出后不安排独立后台任务。
- 缺失、根目录错位或重复附件会报告并保留，不猜测覆盖关系。源码中未完成的链接与代码中出现的 `reference/...` 也保守视为引用。
- WebDAV 使用条件写入、ETag、5 分钟租约和逐文件检查点。远端删除/替换前保存本地副本；缺失 ETag 或竞争写入时停止操作。
- 同步冲突或启用同步但一小时内未成功同步时暂停永久清理。巡检仍处理可恢复移动。
- macOS 用 AES-GCM 将应用密码加密后存入当前用户的 DeskMosaic 私有目录。从使用钥匙串的旧版升级后，在笔记本同步设置里重新填一次 Nextcloud 应用密码并保存。Windows 继续使用当前用户的 DPAPI。两端都将凭据存储独立于笔记库，网络层拒绝重定向。

## 构建与维护

`src/` 是可维护源码；`NotebookWeb/` 是**已提交的离线发布资源**，供 Xcode 文件夹资源与 Windows 嵌入资源共同使用。修改源码或依赖后必须重新生成，不能只修改生成的 `app.js`。

```bash
cd Notebook
npm ci
npm run build
npm test
npm exec prettier -- --check 'src/*' 'tests/*.mjs' build.mjs
```

离线资源包含 Vditor 4.0.0（MIT）、Markdown-it 14.3.2（MIT）和 Lucide 1.49.0（ISC）的许可文本。Vditor 自带的第三方资源保留上游文件和许可声明；不复制其他笔记软件的管理、同步代码。

原生文件服务检查可在 .NET 8 环境执行，只替换宿主主题依赖，实际测试生产文件操作：

```bash
dotnet run --project Notebook/tests/native/NativeChecks.csproj
# Windows 构建后校验每个嵌入资源与源码 SHA-256：
dotnet run --project Notebook/tests/native/NativeChecks.csproj -- \
  'WinAssistant/bin/Release/net8.0-windows/win-x64/DeskMosaic.dll' Notebook/NotebookWeb
```

浏览器验收使用隔离测试库，会清空 `/tmp/notebook-ui-test-library`，绝不打开实际笔记库。先在 `Notebook/` 运行 `node tests/preview-server.mjs`，另启 Chromium/Chrome 的调试端口 9223，再执行 `python3 Notebook/tests/browser-checks.py`。该脚本覆盖原始代码复制、附件写入/延迟回收/跨模式撤销、外部编辑冲突处理、冲突期间退出保护、图片预览及重新打开、浅深主题及 900×600 窗口布局。模拟桥接仅用于开发，生产窗口必须使用原生文件服务。

`tests/code-activation-browser-checks.mjs` 另外覆盖 WebKit 与 Chromium 的实际鼠标点击、空代码块和拆分文本节点、空行及源码持久化、两主题分隔条与键盘/鼠标调宽。需要预先在临时目录安装 Playwright 和对应浏览器，使用 Node 22，参数为 Playwright 的 `index.mjs` 绝对路径及 `webkit` 或 `chromium`；复用上述隔离预览服务，不连接实际笔记库。

`tests/code-copy-browser-checks.mjs` 使用相同参数和隔离服务，覆盖预览及编辑状态下的代码复制、终端 HTML/纯文本混合粘贴、块内全选删除与撤销，以及独立窗口的共享请求、保存写回、取消、撤销、围栏正文和前后段落保留。原生弹窗返回由测试桥接模拟；macOS 原生快捷键与两端窗口关闭确认仍需实机验收。macOS 和 Windows 共用复制与代码编辑逻辑，原生剪贴板写入不追加换行。

冲突按钮回归使用单独目录 `/tmp/notebook-conflict-ui-library`：在 `Notebook/` 运行 `NOTEBOOK_PREVIEW_ROOT=/tmp/notebook-conflict-ui-library NOTEBOOK_PREVIEW_PORT=4174 node tests/preview-server.mjs`，再用 Node 22 运行 `tests/conflict-browser-checks.mjs <Playwright index.mjs 的绝对路径> webkit`，并对 `chromium` 重复运行。覆盖保留本地、采用在线、人工合并、空在线版本、锁定与权限错误的可见性及重试、在线再次修改后的重新对照，以及慢请求中关闭/重开和防止重复提交；处理后校验正文实际字节、冲突状态与整篇笔记同步结果。

## 本轮验证范围

Linux 环境已验证共享逻辑、真实 Vditor 浏览器交互、生产 Windows 文件服务及 Windows Release 构建/单文件发布。Windows 原生窗口、WebView2 运行时和 DPAPI 需要 Windows 实机验收；macOS 缺少 Xcode，尚未编译或实机验证。当前 Nextcloud 的锁、Text 默认只读配置与正常关闭行为已在实际服务器核验；冲突、断网及错误恢复使用隔离库验证。

发布前应在两端补做：拖拽/图片粘贴、原生剪贴板、窗口拖动/缩放/关闭/重开、退出保存失败、睡眠唤醒、凭据重启读取；再对真实 Nextcloud 测试双向新增/修改/删除、断网重连及双设备冲突。大量附件通过内存 Base64 桥接，超大单文件的内存表现尚未压测；笔记界面当前为中文。

## 多设备同步保障

正文、元数据及附件按整篇笔记汇总；同一笔记任一文件失败即标记该项未完成，其他可同步的完整项目继续完成。“同步结果”提供每项结果、具体错误和重试入口。网络等待不占用本地保存队列，同步中继续编辑的新内容保留并进入后续重试；异常空库或大批文件消失触发删除保护。服务器永久应用锁需先处理对应在线编辑状态，客户端不会强制清锁。Nextcloud Text 即使设为默认只读，打开文件时也可能创建应用锁。

参考 [Joplin 的离线优先同步](https://joplinapp.org/help/dev/spec/sync/)与[租约规范](https://joplinapp.org/help/dev/spec/sync_lock/)，采用本地副本、逐文件检查点、条件写入和冲突留存。两端原生定时器每 5 分钟触发一次双向同步（应用运行期间，窗口隐藏也触发）；启动、唤醒、保存连接配置和手动同步会立即尝试。5 分钟不用于决定哪个版本获胜。

- 比较本地、在线与上次成功同步的 SHA-256；双方都修改，或删除与修改相撞时，保存双方副本，停止相关删除。正文可展开对照并手动合并；原始冲突副本不会因选择或合并而移除。
- 冲突窗口在对应项目内显示处理中与具体错误，防止弹窗遮住页面提示；失败后恢复按钮，可重新读取在线版本。重新对照不覆盖已输入的合并正文，旧在线快照仍留存；处理成功后继续同步整篇笔记并刷新结果。
- 上传/删除使用 ETag 条件，服务器版本变化时终止写入。租约接近过期时续期，实际修改前校验独占租约；已过期的本机租约不复活，重新同步获取新租约。
- 网络等待后重读本地文件；同步期间新输入的草稿单独保留。下载与在线删除先保留本地副本，冲突解决时最新本地正文同样备份。
- 回收及移动目的地先上传，再传播旧位置删除。删除集合中发现远端编辑时，保留全部在线元数据与附件，避免笔记消失；完成冲突处理后下次同步继续。
- 每个成功文件独立落盘检查点，断网重试不把已经下载的版本误当成新删除。未解决冲突和过期同步状态暂停附件永久清理。

这些行为经模拟多设备、断网、条件写入竞态和真实浏览器测试；真实 Nextcloud 多设备联调仍需实际服务器。不要把同步视为独立历史备份，设备应使用同一更新版本。

Windows 笔记窗口为 WebView2 外侧保留 10 DIP 的原生缩放命中区，外框仍为 1 DIP 细线；最大化时取消额外留边。macOS 继续由 AppKit 的原生可缩放窗口处理边缘命中，无须为 WKWebView 保留同样的空白区域。窗口边缘与四角的拖拽、高 DPI 和最大化/还原仍需两端实机验收。


## 图片编辑与同步性能

可编辑预览中的图片作为完整对象选中，以轮廓提示选中状态；Backspace/Delete 删除整个图片引用，不展开隐藏的路径标记。源码模式仍可编辑图片名称与路径。删除、切换模式撤销以及附件回收后撤销恢复均有真实浏览器回归测试；原生输入立即标记为待保存，避免在编辑器延迟回调之前切换笔记漏掉删除。

参考 [Joplin 的逐项同步状态](https://joplinapp.org/help/dev/spec/sync/)和[周期性租约](https://joplinapp.org/help/dev/spec/sync_lock/)，结合 [Nextcloud 的 PROPFIND/ETag](https://docs.nextcloud.com/server/latest/developer_manual/client_apis/WebDAV/basic.html)，实现兼容通用 WebDAV 的增量检查，而不依赖 Joplin Server 专有 delta API：

- 目录扫描同时最多 3 个请求，读取成功属性中的 ETag。同步检查点保存内容哈希和 ETag；两边均与检查点一致时跳过远端文件下载。旧检查点及不提供目录 ETag 的服务器自动回退到内容比对。
- 改动、删除和冲突仍使用原有内容哈希、条件写入、隔离备份与逐文件检查点。没有用时间戳判断哪个版本获胜。
- 同一轮内已建立的目录不重复 MKCOL；租约接近过期才续期，实际修改前验证锁归属，过期或失效立即停止。
- 界面显示目录扫描数和文件处理进度。5 分钟自动同步间隔保持不变。

模拟的 100 个未变附件测试中，文件传输请求为零；除目录扫描外，只需整轮锁的取得、校验、释放三个请求。新增、修改、双设备冲突、远端删除、ETag 缺失、租约失效和下载期间本地变化均有回归测试。真实 Nextcloud 服务端耗时和账号联调尚未实测。

新增浏览器检查：`python3 Notebook/tests/image-browser-checks.py`。目录解析检查先运行 `Notebook/node_modules/.bin/esbuild Notebook/src/webdav.mjs --bundle --format=iife --global-name=WebDAVList --outfile=/tmp/notebook-webdav-test.js`，再执行 `python3 Notebook/tests/webdav-browser-checks.py`；两者均复用上述隔离预览服务器和 Chrome 调试端口。

非图片附件在可编辑预览中显示类型与文件名；点击用系统默认程序打开，右键可选择“打开附件”或“另存为”。附件面板也提供打开、另存为与插入正文。源码模式可编辑原始链接。光标留在代码块时，导入的附件放在代码块之后，保留原代码。中文、括号、方括号和百分号文件名有格式与浏览器回归测试；预览控件不进入 Markdown，也不修改文件内容。

另存为使用 Windows/macOS 系统保存对话框，取消不写文件，确认后以临时副本替换目标，原附件保留在笔记目录。Windows 生产文件服务已验证字节复制、覆盖和原附件保留；macOS 系统对话框和默认程序打开仍需实机验收。

浏览器检查：`python3 Notebook/tests/attachment-browser-checks.py`，使用前述隔离预览环境。当前非图片附件采用紧凑文件入口，不内嵌 PDF 阅读器。

## 表格与正文右键操作

点击表格按钮展开 10×10 网格，悬停预览“列数×行数”，点击立即插入（行数包含表头）。方向键选择、回车插入，Esc 或点击外部取消；“自定义…”支持更多行列的数字输入。表格在可编辑预览中直接编辑；右键单元格可在上方/下方插入行、左侧/右侧插入列、删除当前行列、设置列对齐、清空单元格和删除表格，并可设置单元格内文字样式。整表删除（包括删除最后一行或列）需要确认，支持撤销。插入或删除表头时保留 Markdown 要求的单一表头，保留其余单元格原有内容。

新建尺寸交互参考 Joplin；右键行列操作参考 [Typora 表格编辑](https://support.typora.io/Table-Editing/)及 [Tiptap 表格命令](https://tiptap.dev/docs/editor/extensions/nodes/table)。正文右键提供加粗、斜体、删除线、行内代码、标题、列表、引用、链接、代码块及撤销/重做，操作保留文字选区；预览代码块内禁用不适用的格式。两端共用同一编辑器实现，正文仍保存标准 Markdown。

浏览器检查：`python3 Notebook/tests/table-browser-checks.py`，复用前述隔离预览环境；验证网格选择、取消、直接创建、行列增删、列对齐、表头变化、内容保留、源码往返、撤销重做与文字格式。

正文与表格内的右键菜单包含复制、剪切和粘贴文本，通过 Windows/macOS 原生剪贴板读写；菜单操作保留原选区，剪切和粘贴可撤销。正文、列表及源码默认行距为 1.5，段落额外间距为 4px。工具栏右侧“显示”可调整行距（1–2.5 倍）及段落额外间距（0–32px），支持即时预览、取消回退、恢复默认和本机保存。工具栏提供 H₁/H₂/H₃ 三个直接标题按钮，保留原标题快捷键，新按钮不增加快捷键；任务按钮名为“任务/多选框”。

显示设置及标题回归：`python3 Notebook/tests/display-browser-checks.py`，验证保存重启、两种模式、取消及默认值、三级标题和网格直接插入。

附件面板分为正在引用、待回收和已回收三页；待回收项可直接“立即回收”，已回收项可“恢复并插入”或确认“永久删除”。手动操作同时检查已保存正文、当前草稿和恢复稿。重复上传同名且内容相同的文件复用已有附件，回收中的同文件恢复原路径；同名但内容不同的文件保留为独立附件。不存在且未被引用的残留元数据清理，仍被引用的缺失文件继续报告。异步面板更新只展示最新请求结果。

新增回归：`python3 Notebook/tests/clipboard-attachment-browser-checks.py`，使用 `NOTEBOOK_PREVIEW_PORT=4174 node tests/preview-server.mjs`（在 Notebook 目录运行）与同一 Chrome 调试端口，验证两种模式下的右键剪贴板与撤销、重复导入单条记录、立即回收、永久删除取消/确认。

## 独立网页笔记服务 / PWA

同一套 Vditor 编辑器及 Markdown/附件/冲突处理运行在桌面原生宿主和网页端。网页端不是 Nextcloud 插件，通过独立 Node 服务转发标准 WebDAV。电脑使用三栏，手机使用笔记本、笔记列表、编辑页面的分层导航；两种主题共享，手机工具栏可横向滑动，屏幕键盘通过 visual viewport 调整编辑区。

- 网页笔记本需要自行部署。下文使用 `notes.example.com` 和 `cloud.example.com` 作为示例，请换成你自己的 HTTPS 域名。
- 登录使用笔记本独立账号，SQLite 保存单用户账号及带随机盐的 scrypt 密码哈希，不调用首页身份服务。通过服务器命令生成一次性设置链接，在网页自行设置用户名和至少 12 字符的密码；链接 24 小时有效，仅能使用一次。HttpOnly、Secure、SameSite=Strict 会话支持退出撤销；重设账号会使全部旧会话失效，已有笔记和 WebDAV 配置保持。
- 首次登录填入桌面端相同的专用 WebDAV 文件夹地址、Nextcloud 用户名及应用密码。服务器校验后以 AES-GCM 加密保存到持久卷，保留上一版加密备份；客户端只获得地址及账号标识，应用密码不会进入浏览器存储。
- 默认同步全部 `main.md`、笔记本/笔记元数据、回收记录及附件清单到 IndexedDB。附件只有目录占位，图片在打开笔记时、其他附件在打开/保存时下载。未下载的附件不是删除；后台正文保存不会为了回收而下载它。移动或永久删除含未下载附件的目录需先联网取得完整字节。
- 本地保存使用 IndexedDB 事务；提交失败不发布内存中的替换内容，并显示保存失败。未同步的正文、草稿、文件移动和删除标记、共同版本及冲突都持久保留。应用恢复前台、网络恢复、编辑后及前台周期触发同步；手机后台没有定时执行保证。
- 使用现有同步锁、共同内容哈希、ETag 条件写入与冲突双副本，不能以时间戳覆盖另一台设备。按需下载的附件把共同版本与字节一起保存，由同步队列导入检查点；移动集合中任何附件的远端改动会保护原集合的笔记元数据。
- Service Worker 只缓存编辑器资源，不缓存身份接口和 WebDAV 响应。应用资源按内容哈希分版，新版本在下一次启动激活，不在编辑中强制刷新。联网首次加载完成后可在 Safari 添加到主屏幕。
- 登录默认记住 90 天，无需每次打开重新输入；用户名/密码字段支持系统密码管理器自动填充，iPhone 可用 Face ID 解锁保存的密码（[Apple 说明](https://support.apple.com/en-us/108411)），暂未实现 WebAuthn 通行密钥。已登录设备可以在会话有效期内离线打开本机副本；退出会关闭离线访问入口但保留未同步数据。浏览器持久存储申请是否批准由系统决定，清除网站数据会删除本机副本；同步设置中提供本机备份导出。现代浏览器通过 Web Locks 阻止同一笔记库在同一浏览器的两个窗口同时编辑。

服务和测试需要 Node 22.13 或更新版本。先在仓库根目录运行 `npm --prefix Notebook ci && node Notebook/build.mjs`，再进入 `Notebook/deploy`，按示例创建仅本机保存的 `.env`。请设置自己的服务地址、Nextcloud 来源和至少 32 个随机字符的 `NOTES_SECRET`。服务绑定本机的 18083 端口。可按 `nginx.conf.example` 配置 HTTPS 反向代理。

```sh
cd Notebook/deploy
cp .env.example .env
# 编辑 .env，填写实际部署值后再启动
docker compose up -d --build
docker compose exec notes node server/manage-account.mjs invite
```

`data/` 需要容器中的 UID 1000 可写。请备份持久卷和服务密钥，恢复时使用同一密钥。代理仅接受 `NOTES_DAV_ORIGIN` 指定的 Nextcloud 来源，文件传输上限为 64 MB。

验收（只操作 `/tmp` 测试库，不连接生产网盘）：启动 Chrome 调试端口 9223，再启动 `node Notebook/tests/pwa-fixture-server.mjs`（4175），依次运行 `python3 Notebook/tests/pwa-browser-checks.py` 和 `python3 Notebook/tests/pwa-layout-browser-checks.py`。覆盖一次性账号设置、独立登录、加密 WebDAV 设置、默认文字缓存、离线重启/编辑/再重启、联网冲突、退出访问关闭、390/768/1440px 双主题布局、存储失败以及附件移动期间另一设备修改保护。Node 服务测试通过 `npm --prefix Notebook test` 运行，需要本地监听权限。真实 iPhone Safari、主屏幕安装和真实网盘的首次连接仍需使用实际账号验收。

WebDAV 请求在网页代理、Windows 和 macOS 都显式使用 `Accept-Encoding: identity`，保证读取到的 ETag 可用于条件写入和释放同步锁。有效锁保持互斥，界面等待时每 5–8 秒自动重试；网页退到后台或离线暂停重试，回到前台继续。旧版遗留锁依租约到期处理，不强制删除有效锁。

macOS 校验 WebDAV 根目录时直接使用配置中的文件夹 URL，避免新版 Foundation 将空相对路径解析为 nil 后误报“同步请求超出已配置目录”。后续请求仍检查 HTTPS、主机、端口和目录边界。`MACAssistantTests/NotebookDAVURLTests.swift` 覆盖根目录、子文件、附件名称编码、中文目录、端口和越界路径；Windows 使用 .NET `Uri` 解析，空路径会返回原目录，无需相同修补。

手机网页（≤760px）使用底部“笔记本 / 笔记 / 同步 / 主题”导航，避开 Home 指示条，为内容预留底栏高度；顶部只保留名称和状态。电脑/平板三栏及桌面原生菜单不变。iOS 顶部采用不透明状态栏、固定标题栏和一致的主题背景；系统层模糊仍需真实 iPhone 检查。

手机笔记默认只读，点击“开启编辑”才允许修改并展示编辑栏；“完成编辑”保存后恢复只读，切换笔记也恢复只读。独立“选项”按钮在两种状态下均可打开设置。布局监听可见视口的高度及滚动偏移，键盘弹出期间取消底部 Home 安全区占位。浏览器回归覆盖只读输入不会改文、编辑切换、显示弹窗及模拟键盘视口移动；真实 iPhone 键盘仍需实机验收。

“选项”提供默认开启的“自动换行”，Windows、macOS 和网页共用；旧配置缺失字段也默认开启。代码源码/预览使用软换行保留缩进，表格单元格及长网址尽量按可用宽度显示。关闭恢复横向滚动，保存按本机记忆，不修改 Markdown 正文或复制内容。追加换行验收：在 PWA 两组浏览器检查后执行 `python3 Notebook/tests/wrap-browser-checks.py`，覆盖双主题、手机/电脑宽度、编辑状态、取消/保存/重启/默认及原文字节不变。

连续回车产生的额外空段落用标准 `<br />` 独立段落保存，在预览中还原为可编辑空段落，笔记切换、源码/预览切换和重启后保留间隔。已有 Markdown 顶层多空行也会显示相应间隔；普通段落分隔、代码块内部空行保持原样，原始 HTML 保守处理。空白新笔记和代码/表格末尾的自动光标占位不存成额外间隔。验收：PWA 两组浏览器检查后运行 `python3 Notebook/tests/blank-lines-browser-checks.py`，覆盖真实连续回车、尾部空段落、后续输入、笔记切换及离线重启。

工具栏和手机阅读栏的入口统一称为“选项”。回车行为可选“Enter 换段，Shift+Enter 换行”（默认）或“Enter 换行，Shift+Enter 换段”，仅影响可编辑预览的普通正文；代码、列表、表格、标题、引用和源码沿用原规则。设置在本机保存，取消回退、恢复默认及重启记忆与行距设置一致。段内显式换行以行内 `<br />` 保存，连续换行不会误变为多个段落。手机支持仅发送 beforeinput 的键盘，输入法确认不拦截。PWA 两组浏览器回归后执行 `python3 Notebook/tests/enter-behavior-browser-checks.py` 验证键盘规则、连续换行、保存/切换/重启、手机输入及特殊块排除。

长代码笔记使用按可见区域触发的分批语言识别与高亮；完整正文仍保留在编辑器，复制和保存不依赖屏幕外高亮完成。切换笔记会清理旧任务，纯正文仍需全文解析。成熟项目参考、内存边界、实测数据和验收方法见 [长笔记渲染](docs/long-notes.md)。

## 代码块纯文本编辑与独立窗口

代码块粘贴始终取剪贴板的纯文本，忽略终端提供的 HTML/RTF 颜色与排版，只将 CRLF/CR 统一成 LF；缩进、Tab、内部空行与末尾空格保留。按实际代码选区处理全选、选中删除、剪切及粘贴，避免 WebKit 将事件目标定位到外层编辑器后误作普通 Markdown。从高亮预览直接拖选文字后进入编辑仍保留选区；预览选区及落在外层 PRE 边界的选区会映射到同一代码正文，删除和粘贴只替换选中内容，保留代码围栏与前后段落。macOS 原生窗口显式转发 Cmd+A/C/X/V/Z，支持全选、复制、剪切、粘贴与撤销/重做。

Windows 和 macOS 的“弹出编辑”使用独立原生窗口承载同一套离线 CodeMirror 编辑界面，使用主笔记窗口相同的颜色变量、字号、8px 圆角和紧凑工具栏；两端均不挂接为随主窗口移动的子窗口，主窗口可独立拖动。初始自动换行沿用本机“选项”。支持 Tab、回车、全选、删除及窗口内撤销，Ctrl/Cmd+S 或“保存并返回”将内容写回原块并保存笔记，笔记撤销可整体撤回这次修改。取消和关闭不改动正文，有未保存修改时先确认放弃；窗口未关闭时阻止退出，以免丢失草稿。弹出期间暂缓笔记自动同步与外部正文重载；若原块被替换，返回代码会保留在可复制的恢复对话框中。代码中的 Markdown 围栏会自动扩大外层围栏长度，保存重开仍是代码正文。PWA 保持原有就地编辑，不显示原生弹窗入口。

Windows 在笔记就绪后于后台预加载一个空的 WebView2 编辑窗口，提前加载离线脚本；点击“弹出编辑”时才传入当前代码、主题和换行设置。预加载不读取笔记正文、不暂停同步，也不抢焦点或显示任务栏按钮。用过的窗口关闭后销毁，再准备一个全新的空窗口；预加载不可用时回退到按需创建。

弹窗支持语言选择与语法高亮、逻辑行号、当前行与括号匹配高亮、支持语言的代码折叠、查找替换（Ctrl/Cmd+F，含大小写/正则/全词）、跳转行号（Ctrl/Cmd+G）、Tab/Shift+Tab 缩进、撤销重做、自动换行、字号调整和复制全部。状态栏显示光标行列、总行数、总字符数、选中字符数与 UTF-8/LF；字符按 Unicode 码点计数，换行计一个字符，软换行不增加逻辑行数。语言与正文一起保存回原代码块，并可在笔记中整体撤销；字号和换行仅影响弹窗显示。编辑器及语言模块随应用离线打包，不请求外部 CDN；依赖许可证合并至 `NotebookWeb/CODEMIRROR-LICENSE`。

原文中的长代码块正文滚动区高度上限统一为 400px（原生 WebView 的旧实现常回落到 200px），预览和就地编辑一致；短代码保持自然高度，不强行增加留白。

弹窗回归：复用隔离预览服务，执行 `node tests/code-editor-browser-checks.mjs <Playwright index.mjs 绝对路径> webkit`，并对 `chromium` 重复执行，覆盖两主题、语言高亮/折叠、Unicode 统计、选择删除/撤销、查找、跳转、字号换行、保存与取消确认和最小窗口布局。原生主窗口拖动与弹窗独立、原生系统关闭及快捷键仍需 macOS/Windows 实机验收。 Windows 还需覆盖预加载未完成时立即弹出、连续打开不同代码块、切换主题后打开，以及退出时释放空窗口；首次与后续点击到可输入的耗时应在实机分别测量。
